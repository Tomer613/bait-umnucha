# אפיון: מסך יצירת מודעות ומכתבים

**סטטוס:** כמעט סגור. ההמרה של קובצי הוורד ממתינה לקבצים (סעיף 7.1).
**עדכון אחרון:** 15.10.2026

---

## 1. רקע ומטרה

ללקוח יש קובצי וורד רבים מהשנים האחרונות עם מודעות לדיירים, ורובן חוזרות על עצמן (נזילה, ניקיון, פינוי, פנייה לעירייה, כספים ועוד). היום כל מודעה נפתחת מחדש בוורד, ומעדכנים בה ידנית תאריכים ושמות.

**המטרה:** ספריית תבניות מסודרת בתוך המערכת. בוחרים נושא, התבנית נטענת מיד לעורך, **השדות שצריך לעדכן מודגשים בבירור**, ומפיקים מודעה מוכנה להדפסה, למייל או לווצאפ תוך פחות מדקה.

### מה קיים היום (אשף המכתבים)
- 6 תבניות קבועות בקוד, עם קטגוריה ותת-קטגוריה.
- 3 משתנים אוטומטיים: `{{שם_בניין}}`, `{{תאריך}}`, `{{חתימה}}`.
- עריכה בתיבת טקסט פשוטה, תצוגה מקדימה עם כותרת החברה והלוגו, הדפסה ופתיחת מייל לכל הדיירים בעותק מוסתר (BCC).

האפיון הזה מרחיב את האשף הקיים ולא מחליף אותו.

## 2. מבנה הספרייה

```
קטגוריה                 נושא (= תבנית)
─────────────────────────────────────────────
תקלות ותחזוקה      →   נזילה
                   →   השבתת מעלית
                   →   הפסקת מים
ניקיון ופינוי      →   ניקיון חדר מדרגות
                   →   פינוי כללי בבניין
                   →   פינוי חפצים מהחניון
רשויות             →   פנייה לעירייה
                   →   הדברה
כספים              →   עדכון דמי ועד
                   →   גבייה מיוחדת
                   →   תזכורת חוב
חגים ומועדים       →   ברכת שנה טובה
                   →   הנחיות לסוכות
```
_(הרשימה להמחשה. הרשימה האמיתית תיבנה מקובצי הוורד, ראו סעיף 7.)_

- **שתי רמות:** קטגוריה ← נושא. לכל נושא יש תבנית בסיס אחת _(ראו שאלה 3 לגבי גרסאות)_.
- המנהל מוסיף, עורך, מוחק ומשנה סדר של קטגוריות ונושאים.

## 3. שני סוגי שדות בתבנית

ההבחנה החשובה באפיון היא בין שדות שהמערכת **יודעת למלא לבד** לבין שדות שהמנהל **חייב לעדכן**.

### 3.1 שדות אוטומטיים: `{{...}}`
המערכת ממלאת אותם בעצמה לפי הבניין שנבחר וההגדרות.

| שדה | ערך לדוגמה |
|---|---|
| `{{שם_בניין}}` | רבינא 1 |
| `{{כתובת}}` | רחוב רבינא 1, בני ברק |
| `{{תאריך}}` | י"ד בתשרי תשפ"ז · 15.10.2026 (לפי הגדרת התאריך) |
| `{{חתימה}}` | בברכה, בית ומנוחה |
| `{{שם_מנהל}}` | (מתוך פרטי החברה) |
| `{{טלפון_חברה}}` | 052-7623803 |

בעורך הם מוצגים כ**תגית כחולה** עם הערך שנמולא. אין צורך לגעת בהם.

### 3.2 שדות לעריכה: `<...>`
מסמנים מידע שמשתנה בכל פעם: תאריך הניקיון, שעת ההשבתה, שם הקבלן, סכום. הסימון הוא סוגריים משולשים, כמו שהצעת:

> ביום `<תאריך>` בשעה `<שעה>` יגיע `<שם הטכנאי>` לתיקון הנזילה ב`<מיקום>`.

**איך הממשק מדגיש אותם:**
- בעורך: **רקע צהוב בוהק עם מסגרת מקווקוות**. אי אפשר לפספס.
- מעל העורך: פס **"נותרו 4 שדות לעדכון"** עם מעבר מהיר לשדה הבא (כפתור או מקש Tab).
- **פאנל "שדות למילוי"** ליד העורך: רשימת כל השדות כתיבות קלט. מילוי שדה בפאנל מעדכן **את כל המופעים שלו** בטקסט. אם `<תאריך>` מופיע פעמיים, ממלאים אותו פעם אחת.
- שדה שמולא הופך **לירוק בהיר** לרגע, ואז לטקסט רגיל.

**סוג השדה נקבע לפי המילה הראשונה בשמו**, וכך מתאים גם רכיב הקלט:

| שם השדה מתחיל ב… | רכיב קלט | תוצאה בטקסט |
|---|---|---|
| `<תאריך…>` | לוח שנה | "יום שלישי, י"ז בתשרי · 18.10.2026" |
| `<שעה…>` | בורר שעה | "10:00" |
| `<סכום…>` | מספר | "1,250 ₪" |
| כל דבר אחר | טקסט חופשי | כפי שהוקלד |

### 3.3 לפני הדפסה או שליחה
אם נשארו שדות צהובים, מופיעה **אזהרה, לא חסימה**: "נשארו 2 שדות שלא עודכנו: `<שעה>`, `<מיקום>`", עם האפשרויות "חזרה לעריכה" ו"להמשיך בכל זאת". לפעמים משאירים שדה ריק בכוונה, למשל כדי למלא בכתב יד.
- שדה שלא מולא מודפס **כקו ריק** (`__________`), בלי סוגריים ובלי צבע.

## 4. מסך יצירת מודעה

```
┌───────────────────────────────┬─────────────────────────────────┐
│ 🔍 חיפוש תבנית…               │  ⚠ נותרו 3 שדות לעדכון  [הבא ←] │
│                               │                                 │
│ ★ מועדפים                     │  ┌───────────────────────────┐  │
│   ניקיון חדר מדרגות           │  │  [לוגו]  בית ומנוחה       │  │
│                               │  │  לדיירי {רבינא 1}         │  │
│ ▼ תקלות ותחזוקה               │  │                           │  │
│   ● נזילה                     │  │      הודעה על נזילה       │  │
│     השבתת מעלית               │  │                           │  │
│ ▶ ניקיון ופינוי               │  │  ביום [תאריך] בשעה [שעה]  │  │
│ ▶ רשויות                      │  │  יגיע [שם הטכנאי]…        │  │
│ ▶ כספים                       │  └───────────────────────────┘  │
│                               │                                 │
│ שדות למילוי                   │  בניין: [רבינא 1 ▾]  (+ עוד)    │
│  תאריך     [📅 18.10.2026]    │                                 │
│  שעה       [🕙 __:__     ]    │  [🖨 הדפסה] [✉ מייל] [💬 ווצאפ] │
│  שם הטכנאי [___________ ]     │  [💾 שמירה כתבנית חדשה]          │
└───────────────────────────────┴─────────────────────────────────┘
```

- **צד ימין:** בחירת תבנית (חיפוש, מועדפים, עץ קטגוריות) ופאנל השדות למילוי.
- **צד שמאל:** העורך, שהוא גם התצוגה המקדימה. עורכים ישירות על דף המודעה, כמו בוורד, וזה מה שיודפס.
- **בחירת תבנית** טוענת אותה מיד לעורך. אם כבר נעשו שינויים, המערכת שואלת לפני שהיא מחליפה.
- **חיפוש** בשם הנושא וגם בתוכן התבנית ("מעלית" ימצא גם "השבתת מעלית" וגם "ביטוח מעליות").
- **מועדפים** (כוכב) ו**אחרונים** בראש הרשימה.

## 5. עיצוב טקסט

מודעות לתלייה צריכות הדגשות: כותרת גדולה, מילים מודגשות ומרכוז. לכן תיבת הטקסט הפשוטה של היום תוחלף ב**עורך עם סרגל כלים מינימלי**:

**B** מודגש · **U** קו תחתון · גודל (רגיל / גדול / ענק) · יישור (ימין / מרכז) · רשימת תבליטים · צבע הדגשה (אדום בלבד, לאזהרות)

בכוונה אין יותר מזה, כדי שהמודעות יישארו אחידות ונקיות.

> **📌 לבדיקה בהמשך:** טבלאות פשוטות (למשל לוח זמנים של ניקיון) ומסגרות סביב טקסט. נחליט אחרי שנעבור על קובצי הוורד ונראה כמה מודעות משתמשות בהם.

- **התאמה לדף אחד:** בהדפסה, הגופן מוגדל או מוקטן אוטומטית כדי שהמודעה תמלא דף A4 אחד בלי לגלוש לדף שני.

## 6. הפצה

| ערוץ | תיאור |
|---|---|
| **הדפסה** | דף A4 עם כותרת החברה, לוגו, שם הבניין, תאריך וחתימה (קיים היום) |
| **PDF** | שמירה כקובץ, לשליחה או לארכיון |
| **מייל** | פתיחת תוכנת המייל עם כל הדיירים בעותק מוסתר (קיים היום) |
| **ווצאפ** | העתקת הטקסט בפורמט מותאם לווצאפ (מודגש עם `*כוכביות*`) ופתיחת ווצאפ. מתאים לשליחה לנציג, שיעביר לקבוצת הבניין. |

### 6.1 מודעה לכמה בניינים בבת אחת
בוחרים כמה בניינים (או "כל הבניינים"). המערכת מפיקה **דף נפרד לכל בניין** עם השם והכתובת שלו, בהדפסה אחת או בקובץ PDF אחד. מתאים להודעות כלליות כמו ברכת חג או עדכון דמי ניהול.

### 6.2 יומן מודעות שהופקו
כל הפקה (הדפסה, PDF, מייל או ווצאפ) נשמרת ביומן: תאריך, בניין, נושא ונוסח סופי.
- בכרטיס הבניין: "מודעות אחרונות". עונה על שאלות כמו "מתי בפעם האחרונה הודענו על ניקיון?".
- אפשר לפתוח מודעה ישנה ולהפיק אותה שוב בלחיצה.
- הנפח זניח, כי מדובר בטקסט בלבד.

## 7. ייבוא קובצי הוורד הקיימים

### 7.1 המרה חד-פעמית (בשלב ההקמה)
**היקף משוער:** 100–200 קבצים.

**מיקום הקבצים:** תיקיית העזר של הפרויקט, **מחוץ למאגר ה-git** (שם נשמרים רשימות וקבצים נלווים). הנתיב המדויק ייקבע כשהקבצים יועברו. כך מודעות ישנות, שעשויות לכלול שמות וטלפונים של דיירים, לא יגיעו ל-GitHub, ואין צורך בהחרגה ב-`.gitignore`.
- גם הקבצים שהסקריפט מפיק (הטקסט המחולץ ודוח הכפילויות) יישמרו באותה תיקייה ולא במאגר. רק רשימת התבניות הסופית, אחרי אישור הלקוח, תיכנס למערכת.

**התהליך:**
1. **חילוץ אוטומטי בסקריפט:** סקריפט מקומי קורא את כל קובצי הוורד ומחלץ מהם טקסט נקי לקובץ אחד. הסקריפט רץ על המחשב ולא שולח את הקבצים לשום מקום.
2. **סינון כפילויות אוטומטי:** הסקריפט מנרמל כל מודעה (מסיר תאריכים, שעות, מספרים ושמות בניינים) ומקבץ מודעות שנשארו כמעט זהות. מכל קבוצה נשמר נוסח מייצג אחד.
3. **עיבוד:** רק הנוסחים הייחודיים נקראים ומעובדים. בכל אחד מסמנים את השדות: תאריכים, שעות, שמות וסכומים הופכים ל-`<...>`, ושם הבניין ל-`{{שם_בניין}}`. במקביל מוצעת חלוקה לקטגוריות ולנושאים.
4. **אישור:** הלקוח עובר על הרשימה ומאשר לפני שהיא נטענת למערכת.

**עלות בטוקנים:** סבירה, ולא צריך לסנן ידנית מראש. מודעה טיפוסית היא חצי עמוד עד עמוד. גם בתרחיש הגרוע, 200 מודעות שונות, מדובר בקריאה בהיקף של ספר קצר. אחרי סינון הכפילויות בסקריפט צפויות להישאר כמה עשרות מודעות ייחודיות בלבד.
- קבצים בפורמט הישן **`.doc`** (לפני וורד 2007) קשים יותר לקריאה אוטומטית. אם יש כאלה, אפשר להמיר אותם בבת אחת ל-`.docx` (בוורד או ב-LibreOffice), או שנמצא לזה פתרון בסקריפט.

### 7.2 ייבוא בודד מתוך המערכת (לעתיד)
כפתור "ייבוא מקובץ וורד" במסך ניהול התבניות. הטקסט והעיצוב הבסיסי (מודגש, כותרות) נטענים לעורך, והמנהל מסמן את השדות ושומר כתבנית.

## 8. מחולל תבניות ושמירה

### 8.1 העיקרון: מודעה היא לא תבנית
- **תבנית** היא נוסח בסיס עם שדות ריקים, וחוזרים אליו שוב ושוב.
- **מודעה** היא עותק חד-פעמי של תבנית, ממולא לתאריך ולבניין מסוימים.

עריכה במסך היצירה **לא משנה את התבנית** כל עוד לא לחצו במפורש על שמירה. כך לא יקרה שתבנית "נזילה" תיפתח בפעם הבאה עם תאריך מלפני חודשיים.

### 8.2 שלוש אפשרויות שמירה
בחלק התחתון של מסך היצירה יש כפתור **"שמירה"** עם תפריט:

| אפשרות | מתי משתמשים | מה קורה |
|---|---|---|
| **שמירה כתבנית חדשה** | ערכתי תבנית קיימת וקיבלתי נוסח שימושי אחר, או כתבתי מודעה מאפס | חלון קטן: **שם** (ברירת מחדל: "<שם המקורית> – עותק"), **קטגוריה** (ברירת מחדל: של המקורית, או "קטגוריה חדשה…"). התבנית המקורית לא משתנה. |
| **עדכון התבנית "נזילה"** | שיפרתי את נוסח הבסיס, ורוצה שמעכשיו הוא ייטען תמיד | אישור: "התבנית 'נזילה' תוחלף בנוסח הנוכחי". הגרסה הקודמת נשמרת בהיסטוריה (8.5). |
| _(בלי שמירה)_ | שימוש רגיל: מילאתי, הדפסתי, סיימתי | כלום. המודעה נרשמת ביומן המודעות (6.2) ולא בספריית התבניות. |

- השם חייב להיות ייחודי בתוך הקטגוריה. אם השם קיים, המערכת מציעה שם אחר.

### 8.3 שמירה חכמה של שדות
כששומרים כתבנית מודעה שכבר מולאה בה חלק מהשדות, המערכת **זוכרת אילו ערכים הגיעו משדות** ושואלת:

```
בתבנית החדשה, מה לעשות עם הערכים שמילאת?
  ● להחזיר אותם לשדות לעריכה (מומלץ)
      <תאריך>, <שעה>, <שם הטכנאי>
  ○ לשמור את הערכים כטקסט קבוע
```
כך תבנית חדשה שנוצרה ממודעה אמיתית לא "תינעל" על התאריך שהיה בה.

### 8.4 מחולל: יצירה ועריכה של תבנית
אפשר להיכנס למחולל משלושה מקומות: כפתור **"תבנית חדשה"** במסך היצירה, "שמירה כתבנית חדשה" (8.2), או ממסך ניהול התבניות (8.6).

כלי העזר בעורך התבנית:
- **"הוספת שדה אוטומטי"**: תפריט של השדות מסעיף 3.1. אין צורך לזכור את התחביר.
- **"הוספת שדה לעריכה"**: מקלידים שם (למשל "תאריך הפינוי"), והשדה נוסף עם הסוגריים.
- **סימון טקסט ← "הפוך לשדה":** מסמנים בעכבר "18.10.2026" בתוך הטקסט, לוחצים, ונותנים שם ("תאריך הפינוי"). הטקסט הופך ל-`<תאריך הפינוי>`. זו הדרך המהירה ביותר להפוך מודעה שהודבקה מוורד לתבנית.
- **שם השדה קובע את סוגו** (תאריך / שעה / סכום / טקסט), לפי הטבלה בסעיף 3.2. המחולל מציג ליד כל שדה את הסוג שזוהה.
- **תצוגה מקדימה** לפי בניין לדוגמה, כדי לראות איך השדות האוטומטיים יתמלאו.

### 8.5 היסטוריית גרסאות
- כל "עדכון תבנית" שומר את הגרסה הקודמת. נשמרות **5 הגרסאות האחרונות** לכל תבנית.
- "שחזור גרסה קודמת" מתוך מסך ניהול התבניות.
- הנפח זניח, כי מדובר בטקסט בלבד.

### 8.6 מסך ניהול התבניות
**רק במסך ההגדרות**, לשונית **"תבניות מודעות"** ([00-principles.md](00-principles.md)). במסך היצירה יש קישור "ניהול תבניות ←" שמוביל ללשונית הזו.
- במסך היצירה נשארות רק פעולות העבודה: **שמירה כתבנית חדשה** ו**עדכון התבנית שנטענה** (8.2). כל השאר נעשה כאן:
- עץ קטגוריות ונושאים עם גרירה לשינוי סדר ולהעברת תבנית בין קטגוריות.
- הוספה, שינוי שם ומחיקה של קטגוריות. קטגוריה שיש בה תבניות אי אפשר למחוק עד שמעבירים אותן.
- שכפול, עריכה, שינוי שם ומחיקה של תבניות.
- מחיקת תבנית מעבירה אותה **לסל מחזור ל-30 יום**.

```
notice_log
 ├─ id, templateId, buildingId

 └─ createdAt
```

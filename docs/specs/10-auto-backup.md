# אפיון: גיבוי אוטומטי לגוגל דרייב

**סטטוס:** סגור. ממתין לפיתוח.
**עדכון אחרון:** 16.10.2026
**תלוי ב:** [01-users-and-permissions.md](01-users-and-permissions.md) סעיף 8 (תשתית Supabase)

## 1. רקע ומטרה

אחרי המעבר ל-Supabase הנתונים יישבו בענן. במסלול החינמי של Supabase **אין גיבויים אוטומטיים**. לכן מחיקה בטעות, באג שמשבש נתונים או בעיה בחשבון עלולים לגרום לאובדן מידע בלי דרך לשחזר אותו.

**המטרה:** גיבוי שעובד לבד, כמו הגיבוי של וואטסאפ. המנהל מחבר פעם אחת את הגוגל דרייב שלו, ומאותו רגע המערכת שומרת לשם עותק מלא בתדירות שהוא קבע.

**עקרונות:**
- **לא מטרידים את המנהל.** כל עוד הגיבויים מצליחים, הוא לא מקבל שום הודעה. משימה מופיעה רק כשגיבוי נכשל.
- **אפס עלות.** כל הרכיבים חינמיים: Supabase (pg_cron ופונקציית שרת), Google Drive API ו-15GB האחסון החינמיים של גוגל.
- **החיבור לדרייב חייב להיות ברור מאוד**, צעד אחרי צעד, ולמנהל לא צריך להיות ידע טכני (סעיף 3).

## 2. מיקום והרשאות

- **הגדרות ← מערכת ← גיבוי ושחזור.** זו הלשונית הקיימת, והיא תיבנה מחדש בכרטיס האחיד ([08-settings-structure.md](08-settings-structure.md)).
- **רק המנהל הראשי.** לנציגים אין גישה למסך הזה ולקובצי הגיבוי.

## 3. חיבור לגוגל דרייב: התהליך המלא

### 3.1 מצב התחלתי: לא מחובר
```
┌─ גיבוי אוטומטי ─────────────────────────────────────────────┐
│  ☁  הנתונים עדיין לא מגובים                                  │
│                                                              │
│  חברו את הגוגל דרייב שלכם, והמערכת תשמור לשם עותק מלא של     │
│  כל הנתונים באופן אוטומטי. אין צורך לעשות שום דבר אחרי זה.    │
│                                                              │
│  [ G  חיבור לגוגל דרייב ]                                     │
│                                                              │
│  ⓘ המערכת תקבל גישה רק לתיקייה שהיא עצמה יוצרת              │
│     ("גיבויי בית ומנוחה"). שאר הקבצים בדרייב שלכם לא נגישים לה. │
└──────────────────────────────────────────────────────────────┘
```
עד שמחברים את הדרייב, משימה קבועה מופיעה במסך המשימות: **"הנתונים לא מגובים · חיבור לגוגל דרייב ←"**. הקישור מוביל ללשונית הזו. זה המקרה היחיד שבו מופיעה משימה בלי שגיבוי נכשל, כי מערכת בלי גיבוי היא סיכון.

### 3.2 הצעדים
| # | מה המנהל עושה | מה הוא רואה |
|---|---|---|
| 1 | לוחץ על "חיבור לגוגל דרייב" | נפתח חלון של גוגל |
| 2 | בוחר חשבון גוגל | אם הוא מחובר לכמה חשבונות, גוגל מציג רשימה |
| 3 | מאשר את ההרשאה | גוגל מציג: "בית ומנוחה רוצה גישה לקבצים בגוגל דרייב שהאפליקציה הזו יצרה" ← "המשך" |
| 4 | חוזר אוטומטית למערכת | "מחברים… יוצרים תיקייה ושומרים גיבוי ראשון" (כמה שניות) |
| 5 | סיום | ✓ "הדרייב מחובר. הגיבוי הראשון נשמר." וכפתור "פתיחת התיקייה בדרייב" |

**מעל הכפתור בצעד 1** תופיע שורת הסבר קצרה: "ייפתח חלון של גוגל. בחרו את החשבון שאליו יישמרו הגיבויים ואשרו את הגישה."

### 3.3 מצב מחובר
```
┌─ גיבוי אוטומטי ───────────────────────────────── [פעיל ●] ─┐
│  ✓ גיבוי אחרון: אתמול, 03:00 · 2.4MB                         │
│     הגיבוי הבא: יום שישי, 03:00                               │
│                                                              │
│  יעד        Google Drive · cowboy@gmail.com                   │
│             תיקייה: גיבויי בית ומנוחה  [פתיחה בדרייב ↗]       │
│                                         [החלפת חשבון] [ניתוק] │
│                                                              │
│  תדירות     ( ) כל יום   (●) כל שבוע   ( ) כל חודש            │
│  שמירה      [20] הגיבויים האחרונים (הישנים יותר נמחקים)       │
│                                                              │
│  [גיבוי עכשיו]                                               │
└──────────────────────────────────────────────────────────────┘
```
- **"גיבוי עכשיו"** מריץ גיבוי מיד ומציג את התוצאה במקום: ✓ או סיבת הכישלון.
- **מתג "פעיל"** משהה את הגיבוי האוטומטי בלי לנתק את הדרייב. כשהמתג כבוי, מוצגת משימה "הגיבוי האוטומטי מושהה".
- **"ניתוק"** מבקש אישור: "הגיבויים שכבר נשמרו יישארו בדרייב. גיבויים חדשים לא יישמרו". אחרי הניתוק חוזרים למצב 3.1.
- **"החלפת חשבון"** פותח שוב את תהליך 3.2. הגיבויים הקודמים נשארים בחשבון הקודם.

### 3.4 שגיאות בזמן החיבור
| מה קרה | מה מוצג |
|---|---|
| המנהל סגר את חלון גוגל או לחץ "ביטול" | "החיבור בוטל. אפשר לנסות שוב בכל זמן." והכפתור נשאר |
| הדפדפן חסם את החלון הקופץ | "הדפדפן חסם את חלון גוגל. אשרו חלונות קופצים לאתר הזה ונסו שוב." |
| הגיבוי הראשון נכשל אחרי החיבור | החיבור נשמר, ומוצגת שגיאת גיבוי (סעיף 5) עם "נסו שוב" |

## 4. הגיבוי עצמו

### 4.1 מה נשמר
**הכל**, בקובץ אחד: בניינים, דירות, דיירים, ספר התנועות, הוצאות, גביות מיוחדות, פריסות חוב, פניות והודעות, נציגים (בלי סיסמאות), תבניות מודעות, תבניות דוחות, פרטי החברה והלוגו, וכל הגדרות המערכת.

- **פורמט:** JSON דחוס (zip).
- **שם הקובץ:** `גיבוי_בית_ומנוחה_2026-10-16_0300.zip`. הוא ממוין לפי תאריך, וקל לזהות כל גיבוי.
- **בתוך הקובץ:** גרסת מבנה הנתונים, כדי ששחזור של גיבוי ישן יעבוד גם אחרי עדכוני מערכת.

### 4.2 תזמון
- בשרת (pg_cron של Supabase), **ב-03:00 לפי שעון ישראל**, בתדירות שנבחרה. בתדירות שבועית: כל יום שישי. בתדירות חודשית: ב-1 לחודש.
- הגיבוי רץ גם כשאף אחד לא מחובר למערכת.
- **ברירות מחדל:** כל שבוע, ושמירה של 20 גיבויים (בערך 5 חודשים אחורה).

### 4.3 ניקוי
אחרי כל גיבוי מוצלח נמחקים מהתיקייה הגיבויים שמעבר למספר שנקבע. המערכת מוחקת רק קבצים שהיא עצמה יצרה.

### 4.4 יומן
כל ניסיון גיבוי, מוצלח או כושל, נרשם ביומן: תאריך, גודל, משך וסיבת כישלון. בלשונית מוצג קישור "היסטוריית גיבויים" עם 30 הרשומות האחרונות.

## 5. כשגיבוי נכשל

ניסיון חוזר אוטומטי אחרי שעה, ועד 3 ניסיונות. אם כולם נכשלו:
- **משימה במסך המשימות**, בצבע אדום, עם הסיבה ופעולה אחת לתיקון.
- **מייל למנהל**, דרך שירות המייל שנקבע באפיון 01 סעיף 8.3, כדי שהמנהל יידע גם אם הוא לא נכנס למערכת.

| סיבה | נוסח המשימה | פעולה |
|---|---|---|
| ההרשאה בוטלה בצד של גוגל, או שהסיסמה בגוגל שונתה | "הגיבוי נכשל: החיבור לגוגל דרייב נותק" | חיבור מחדש ← (תהליך 3.2) |
| הדרייב מלא | "הגיבוי נכשל: אין מקום בגוגל דרייב" | פתיחת הדרייב ↗ |
| תיקיית הגיבויים נמחקה | **זו לא שגיאה.** המערכת יוצרת תיקייה חדשה וממשיכה. | |
| שגיאה אחרת או תקלה זמנית בגוגל | "הגיבוי נכשל. ננסה שוב בגיבוי הבא." | גיבוי עכשיו |

**הגנה מפני כשל שקט:** אם עבר זמן כפול מהתדירות בלי גיבוי מוצלח, למשל 14 ימים בגיבוי שבועי, מופיעה משימה גם אם לא נרשם שום כישלון. זה מכסה מקרה שבו המשימה המתוזמנת עצמה לא רצה.

המשימה נעלמת אוטומטית אחרי הגיבוי המוצלח הבא.

## 6. שחזור

בלשונית, מתחת לגיבוי האוטומטי:
```
┌─ שחזור מגיבוי ──────────────────────────────────────────────┐
│  [שחזור מגיבוי בדרייב…]   [שחזור מקובץ במחשב…]              │
│  [הורדת גיבוי למחשב]                                          │
└──────────────────────────────────────────────────────────────┘
```
- **"שחזור מגיבוי בדרייב"** מציג רשימה של הגיבויים בתיקייה (תאריך וגודל), ובוחרים אחד.
- **"שחזור מקובץ במחשב"** משמש לקובץ שהורד ידנית.
- **לפני כל שחזור** המערכת שומרת אוטומטית גיבוי של המצב הנוכחי, בשם `לפני_שחזור_…`. כך אפשר לבטל שחזור שנעשה בטעות.
- **אישור:** חלון שמציג את תאריך הגיבוי ואת מספר הבניינים והתנועות בו, ומסביר שכל הנתונים הנוכחיים יוחלפו. כדי לאשר צריך להקליד "שחזור".
- **במהלך השחזור** הנציגים לא יכולים לשמור שינויים. השחזור לוקח שניות.

## 7. הערות טכניות למימוש

- **פרויקט ב-Google Cloud** (חינמי), שמוגדר פעם אחת על ידי המפתח, לא על ידי המנהל. בפרויקט מגדירים OAuth Client ו-Drive API.
  - ההרשאה היא `drive.file`: גישה רק לקבצים שהאפליקציה יצרה. גוגל מגדירה אותה כהרשאה **לא רגישה**, ולכן לא צריך תהליך אימות ארוך מול גוגל.
  - **חובה להעביר את הפרויקט למצב "In production".** במצב "Testing" החיבור פג אחרי 7 ימים, והגיבויים יפסיקו לעבוד. צריך לבדוק בזמן ההקמה אם גוגל מציגה מסך "אפליקציה לא מאומתת", ואם כן, להשלים את אימות המותג (חינמי).
- **תהליך ההרשאה** מתבצע בפונקציית שרת (Edge Function) עם `access_type=offline`, כדי לקבל מפתח רענון קבוע. המפתח נשמר מוצפן ב-Supabase Vault ולא מגיע אף פעם לדפדפן.
- **הגיבוי:** pg_cron מפעיל פונקציית שרת. הפונקציה קוראת את כל הטבלאות עם הרשאת שרת, דוחסת אותן, מעלה את הקובץ לדרייב, מנקה גיבויים ישנים ורושמת ביומן.
- **גודל:** בהערכה, גיבוי של 8 בניינים עם כמה שנים של תנועות שוקל כמה MB. 20 גיבויים תופסים פחות מ-100MB מתוך 15GB החינמיים.
- **pg_cron רץ לפי UTC.** צריך להמיר כך שהגיבוי ירוץ ב-03:00 לפי שעון ישראל, כולל במעבר לשעון קיץ.
